# RADAR 2.0 implementation and administrator guide

This audit follows the supplied **RADAR 2.0.pdf** (SHA-256 `035dafaf913e3e7dfd1a14a9b1f99bee0306dfbb315a61a8a6b1dcf2c5767029`). It distinguishes implemented workflows from integrations and datasets that still need activation or development. It does **not** certify school safety or claim every advanced feature is finished.

## Open the update

Pull `design/radar-command-dashboard`, run `npm ci`, stop the previous development terminal with Ctrl+C, then run `npm run dev`. Open the **Local** address printed by that Vite instance. If 8787 is occupied, the launcher selects a free API port and points its own Vite proxy there. An explicitly configured busy `PORT` fails with an actionable message. Do not keep using an older tab/server and expect it to acquire new API routes.

The new sidebar entry is **Campus operations** (`/operations`). Room records, reports, individual attendance, SOS response, integrations, inventory, assembly planning, assistance, membership and emergency settings are separate tabs. Existing map, scanning, alerts, incidents, recovery, analytics and offline pages remain available.

A missing route now includes its method/path and `API_ENDPOINT_NOT_FOUND`. `/api/health` reports `apiVersion: "2.1"`. If the top school banner still reports a missing route, check this version through the **same UI origin** (`/api/health`), restart the backend and open the newly printed Vite address. Do not replace a failed workspace request with another school's data.

## School and account setup

The directory contains historical **2020–2021** records for 377 Camarines Norte schools across 12 municipalities, not a verified current DepEd master list. Selecting a school does not invent campus records. Create its workspace, then enter real buildings, floors and rooms.

In **School members**, administrators invite an account that has already registered in this RADAR installation and select its role. Membership is specific to the selected school; it does not grant global administrator access. Revoking access preserves historical records. Use **Emergency settings** to enter actual school contacts/procedures, reporting policy, guardian relationships and check-in follow-up interval.

Supabase's public project URL/publishable key alone cannot activate private database or file storage. Run `npm run setup:supabase` locally and follow [SUPABASE.md](SUPABASE.md). Keep database credentials and service-role keys in the server's environment. **No live connection to the user's Supabase project was verified for this update.** Existing local records are not automatically migrated.

## Optional service activation

Copy `.env.example` to `.env` only if no local `.env` exists; preserve existing settings. The file lists optional keys without secrets.

- **Vision:** set `RADAR_VISION_API_KEY` (server only), optionally `RADAR_VISION_MODEL`. The scan screen asks for consent before actual photos leave the server for `https://api.openai.com/v1/responses`. Findings stay pending until reviewed. Do not upload student faces or sensitive documents unnecessarily.
- **Earthquakes:** set `RADAR_USGS_FEED_ENABLED=true`, then **Campus operations → Feeds & delivery → Fetch official USGS earthquake reports**. Source: `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_day.geojson`; USGS documented GeoJSON feed, source generation freshness checked, Philippines bounding box 116–127°E/4–22°N. Source timestamps/event pages are stored. An empty regional result is not proof that no earthquake occurred.
- **Push:** generate a VAPID pair (`npx web-push generate-vapid-keys`), set server VAPID fields and a `mailto:`/HTTPS subject. Serve the production build over HTTPS. Each user grants browser permission and subscribes from **Feeds & delivery**. Existing subscriptions can be revoked. Private generic lock-screen text avoids exposing roster/location information.
- **SMS:** configure server Twilio SID/token/from and an HTTPS `RADAR_PUBLIC_URL`; users explicitly consent with an E.164 phone number. Publishing an alert with SMS selected creates a durable job, processed at maintenance ticks or the authorized manual process button. Twilio acceptance is recorded separately from signed delivery callbacks. Unknown/failed jobs need staff review; the system does not automatically resend ambiguous messages and risk duplicate emergency texts.
- **Real 3D/360:** room record → prepared asset upload. GLB must be self-contained, embedded textures, max 10 MB. Panorama must be actual equirectangular imagery. First-person mode additionally requires model measurements, a verified starting floor XYZ and an eye height. No model/imagery means unavailable, with 2D fallback. This is a recorded environment, not current emergency conditions.

## Operations, backups and deployment

Use Node 24+ with npm. `npm ci`, `npm test`, `npm run build`; serve `npm start` behind an HTTPS reverse proxy. The backend serves the production SPA and API together; `npm run preview` serves only static Vite preview and is not a complete backend deployment. Configure correct `HOST`/`PORT`, durable storage and `RADAR_PUBLIC_URL`. Never expose the Supabase service-role key to browser builds. Demo SQLite is for development; real schools should use the configured hosted mode, which does not seed demonstration accounts.

Schema initialization is additive and repeatable, retaining existing records. Back up before updates. No destructive automatic downgrade is provided. `GET /api/health` is a process/version/database-driver liveness check; it is not an external provider health guarantee. Monitor process exits, HTTP failures, server logs, job states and backup restores with your deployment platform. Scheduled reminders and jobs require a running backend; they are not a guarantee of external delivery. Authentication throttling uses shared database counters with expiry and hashed account/IP keys. Add gateway rate limits for public production traffic.

For local SQLite: stop writes for a consistent whole-application snapshot, run `npm run backup`. It uses SQLite's backup API for each DB and copies uploaded files to ignored `.backups/<timestamp>`. `.env` is excluded. Backups contain private school records: encrypt, restrict access, keep off-host copies and apply a retention policy. Restore with servers stopped: preserve current data, restore the backup's `data/` to the configured `RADAR_DB_DIR` (default `server/data`) and `original-uploads/` to `server/uploads`; verify permissions, run the updated server and inspect health/school records. The backup command is a local tool, not a remote cloud backup.

For Supabase: enable and verify project backups/PITR according to the project's plan; separately back up private Storage objects (database backups alone do not contain object bytes). Rehearse database **and** Storage restore into a separate project before production use. Do not assume local backup or changing `.env` migrates school data into Supabase.
